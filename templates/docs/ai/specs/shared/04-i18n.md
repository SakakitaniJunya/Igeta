# 多言語対応 (i18n) 設計

> **TL;DR**: <ロケールの決め方と、文言・日時の扱いを 1 文で。例: 文言は catalog、日時は UTC 保存・表示時に変換>
> - 対応する言語と、多言語にする出口は、`person/` の非機能要件が決める。本書はその ID を引く
> - 文言を**コードに直書きしない**。全部 catalog のキー経由 (原則: 生成できるものは手で書かない)
> - 未翻訳キーは**既定ロケールにフォールバックして警告**。空文字や英語キー名を画面に出さない (原則: サイレント縮退禁止)

## 2. 文言カタログ

<!-- 実体の置き場所と、本書 ↔ 実体がずれない仕組み。キー命名は画面 ID / API コードから機械的に導けるようにする -->

| ID | 項目 | 決め | 根拠 |
|---|---|---|---|
| I18N-101 | 置き場所 | <例: `apps/web/messages/<locale>/<feature>.json`> | 機能単位で分割し、機能削除と同時に消える |
| I18N-102 | キー命名 | <例: `<feature>.<screen>.<element>` / エラーは `errors.<CODE>`> | 03-messages の MSG-ID から導ける |
| I18N-103 | 直書き禁止の検査 | <例: JSX / テンプレ内の日本語リテラルを CI で落とす> | 漏れを人が探さない |
| I18N-104 | 複数形・性・数 | <例: ICU MessageFormat を使う / 使わない> | |
| I18N-105 | 変数埋め込み | <例: `{name}` 名前付きのみ。位置引数は禁止> | 語順が言語で変わる |

## 3. ロケール依存の振る舞い

<!-- 文言以外で変わるものを全部列挙する。1 行ずつ「保存形式」と「表示形式」を分けて書く。法的表記・規約は業務フローの約束の文が決める -->

| ID | 対象 | 保存形式 (ロケール非依存) | 表示・入力形式 (ロケール依存) | 決め |
