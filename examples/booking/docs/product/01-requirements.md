# 予約 CLI サンプルの要件定義

> **TL;DR**: 予約の作成・確定・キャンセル、枠の定員、テナント分離を、外部サービスなしで学ぶための架空の要件。

## 関連

| 区分 | 文書 | 対応 ID |
|---|---|---|
| 上流 (depends_on) | なし（最上流。Igeta の使い方を説明する学習用シナリオ） | — |
| 下流 | [機能一覧](../design/basic/01-function-list.md) / [非機能要件](../design/basic/03-nonfunctional.md) / [テスト仕様](../design/test/specs/01-booking.md) | FN-001〜008 / NFR-001〜401 / TST-201〜215 |

## 1. 業務要件

| ID | 業務要件 | 現状の課題 | 受入基準 | 出典 |
|---|---|---|---|---|
| REQ-001 | 開発者が設計と実装の対応を追える | 空の雛形だけでは完成形が分からない | 記入済み設計書からテストと実行コードに到達できる | この学習シナリオ |
| REQ-002 | 設計書の表が実装とずれたら機械が気づく | 文書は書いた直後から古くなる | 図・遷移表・メッセージ表のずれが検査で落ちる | この学習シナリオ |

## 2. 機能要件

| ID | パターン | 要件文 | 対応業務 | 受け入れ条件 |
|---|---|---|---|---|
| REQ-101 | Event | 有効なテナント ID・予約 ID・既存の枠 ID を受けたとき、システムは draft の予約を作成しなければならない | REQ-001 | 作成結果と保存状態が draft |
| REQ-102 | Unwanted | キャンセル済み予約の確定を求めた場合、システムは再確定を拒否しなければならない | REQ-001 | エラーコードと cancelled 状態を確認 |
| REQ-103 | State | 異なるテナントを指定している間、システムは元テナントの予約を返してはならず、null を返さなければならない | REQ-001 | 他テナントの取得結果が null、越境保存は失敗 |
| REQ-104 | Unwanted | 入力不正・対象なし・保存競合の場合、システムは検証可能なエラー情報を保持しなければならない | REQ-001 | 入力不正は 400、対象なしは 404、競合は 409 と詳細コード |
| REQ-105 | Event | 予約を作成・確定・キャンセルしたとき、システムはテナント・予約 ID・枠 ID・注入時刻を含むイベントを配信しなければならない | REQ-002 | 配信済みイベントを順に取り出せる |
| REQ-106 | Event | draft の予約の確定を受けたとき、システムは枠の残数を 1 減らして確定にしなければならない | REQ-001 | 確定後の残数と状態を確認 |
| REQ-107 | Unwanted | 残数が 0 の枠に対する確定の場合、システムは予約と枠を変更せずに確定を拒否しなければならない | REQ-001 | 409 と、予約が draft・枠の残数が 0 のまま |
| REQ-108 | Event | 確定済み予約のキャンセルを受けたとき、システムは枠の残数を 1 戻さなければならない | REQ-001 | キャンセル後の残数が 1 増える |

## 3. 制約

| ID | 制約 | 根拠 | 影響範囲 |
|---|---|---|---|
| REQ-201 | Node.js 22 以上、保存はメモリのみ | 学習の準備を小さくする ([ADR-0001](../adr/0001-in-memory-persistence.md)) | 実行終了でデータは消える |
| REQ-202 | 枠の定員は確定時に消費する | 定員の判定を 1 か所に閉じる ([ADR-0002](../adr/0002-capacity-on-confirmation.md)) | draft は枠を押さえない。確定は先着順 |

## 4. 前提

| ID | 前提 | 未確認/確認済 | 崩れた場合の影響 |
|---|---|---|---|
| REQ-301 | 操作者はローカルの開発者 | 確認済（サンプルの定義） | 外部公開する場合は認証・認可の設計が必要 |
| REQ-302 | 枠は運用側が事前に用意する | 確認済（サンプルの定義） | 枠の作成機能と権限設計が必要になる |

## 5. スコープ外

| ID | スコープ外の内容 | 理由 | 再検討する条件 |
|---|---|---|---|
| REQ-401 | 画面・HTTP・認証・認可・DB/RLS・料金・決済・イベントの購読 | 雛形を学ぶ最小例に限定 | 実案件へ採用する前に要件を定義 |
| REQ-402 | 重複作成の拒否・仮押さえの期限切れ・枠の時間帯の重複判定 | 冪等性と枠管理の方式は案件ごとに異なる | 実案件の要件を決めたとき (RSK-102 / RSK-203) |
