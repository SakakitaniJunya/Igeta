## 1. 最初に知ること（3 分）

Igeta は、要件や設計を Markdown に書き、書き方・参照先・実装との一致を検査する道具です。
予約サンプルは、その使い方を体験するための小さな CLI プログラムです。

| 場所 | 中身 | 最初の扱い |
|---|---|---|
| `docs/guides/` | Igeta の操作手順 | このページ → 実習手順を読む |
| `examples/booking/docs/` | 記入済みの設計書 23 本 (arc42 11 章分) | 完成例として読む |
| `examples/booking/src/` | 設計に対応するコード | 実習の後半で読む |
| `templates/` | 自分の案件へコピーする雛形 | 案件に着手するときに選ぶ |

最初のゴールは「予約作成の要件が、どの機能・コード・テストに対応するか」を説明できることです。
まずは下の 1〜4 を順に進めてください。所要時間は目安です。

## 2. 学習ロードマップ（約 30〜45 分）

| 順 | 開くページ | やること | 次へ進める状態 |
|---|---|---|---|
| 1（5〜10 分） | [実習 §1：起動する](02-booking-sample.md#1-起動する) | clone・依存取得・サンプル実行・検査 | 最後に「サンプル完了」が出て、検査が成功する |
| 2（10 分） | [実習 §2：要件をコードまで追う](02-booking-sample.md#2-要件をコードまで追う) | REQ-101 → FN-001 → Reservation → TST-201 を追う | 作成時の状態が draft になる根拠と実装を指せる |
| 3（5〜10 分） | [実習 §3：検査を一度失敗させて戻す](02-booking-sample.md#3-検査を一度失敗させて戻す) | 図の 1 行を消す → 検査 → 元に戻す | 図とコードがずれると失敗し、戻すと成功する |
| 4（5 分） | [実習 §4：変更後の確認](02-booking-sample.md#4-変更後の確認) | 索引生成・全体検査 | 何を編集するとどのコマンドが必要か分かる |
| 5（案件に着手するとき） | [案件ロードマップ](03-project-roadmap.md) | 自分の利用者・要件を 1 機能分書く | 次に作る文書と、その完了条件が決まる |
