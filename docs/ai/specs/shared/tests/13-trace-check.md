# テスト仕様 — 設計書のつながり (ID の上流・下流、コードの `@trace`、基準)

> **TL;DR**: 決定・要件・機能・画面・API・表・テスト・コードの ID が、欄 (上流・下流) とコードの先頭行で届くかを `TraceCheck` で確かめる。
> 既存の違反は基準ファイルに記録し、新しい違反と基準の増加だけを落とす。`igeta trace <ID>` で ○・△・✗ の木を出す。
> 方針は [ADR-0015](../../../../person/decisions/2026/0015-trace-check.md)。雛形・番号の帯・利用 repo への当て方は テスト仕様 14。

## 0. 規則

**定義**: 表のデータ行で、最初のセルが ID の形 (`idOf`: 英大文字で始まる英数字 + `-` + 3 桁)。
**参照の欄**: 表の見出しが `trace_columns` で上流・下流と宣言された列。参照は、この欄の ID だけを数える (本文・引用・否定の文は数えない)。

| # | 規則 (上流 → 下流) | 違反の重さ |
|---|---|---|
| T1 | 同じ ID の定義が 2 つ以上ある | 違反 |
| T2 | DEC のうち「影響の種類」が `作る物` の行は、下流 (REQ か FN) を 1 件以上指す | 違反 |
| T3 | REQ は、下流に FN を 1 件以上持つ (FN の上流欄が REQ を指すことで届く) | 違反 |
| T4 | FN は、上流に REQ を 1 件以上、下流に SCR か API を 1 件以上持つ | 違反 |
| T5 | SCR は、上流に FN を 1 件以上持つ | 違反 |
| T6 | API は、上流に SCR か FN を 1 件以上持つ | 違反 |
| T7 | TBL は、コード (`@trace`) か TST から 1 件以上参照される | 警告 (基準が空になったら違反) |
| T8 | TST は、テストの文書の定義と、テストのコードの `@trace` の両方に現れる | 違反 |
| T9 | 辺が片方だけに書かれている (A の下流に B、B の上流に A が無い) | △ 警告 (`trace.strictEdges: true` で違反) |
| T10 | `@trace` や欄の ID が、どの定義にも無い (書き間違い) | 違反 |
| T11 | 帯を宣言した節の定義の百の位が、帯と違う (宣言は テスト仕様 14 §0) | 違反 |

**0.1 種類**: 既定は DEC・REQ・FN・SCR・API・TBL・TST。接頭辞と種類の対応は `.igeta.json` の `trace.kinds` で上書きする。T3〜T6 は、その種類の定義が 0 件の repo では検査しない。

**0.2 コードの `@trace`**: ファイルの**先頭行** (MD-09 の概要の行) に、`@trace` の後ろで ID を空白区切りで書く。例 (架空): `// 在庫の単位を表す部品。 @trace SCR-101 FN-010`。2 行目以降の `@trace` は見ない。対象は `trace.code` の glob。glob に入るのに `@trace` が無いファイルは違反。`@trace` だけで ID が 0 件のものは未記入の警告。コードの ID は下流として数える。

**0.3 基準 (段階導入)**: repo 直下の `.igeta-trace-baseline.json` に、違反の指紋 (規則・ID・ファイル。行番号は入れない) を記録する。基準に有る違反は `baselined` と表示して落とさない。基準を減らすのは `igeta trace --update-baseline` だけ。増やすのは禁止し、origin の基準より指紋が増えていたら違反にする (`GitRef.readFileAtRef`・`mergeBase`)。origin が無いときは `cannot-check` にして通さない。T7 は、基準が空になったら `trace.tblRule: "error"` で違反に上げる。

**0.4 `igeta trace <ID>` の出力**: 上流と下流の木を stdout に出す。○ 辺が両方向に揃い、先が定義されている。△ 片方向 (T9)。✗ 必須の辺が無い、または先が未定義 (T10)。`--mermaid` で同じ木を Mermaid の `flowchart TB` でも出す。ファイルは書かない。

## 2. 否定テスト (必須)

| # | 悪用・誤検知 | 期待 |
|---|---|---|
| N1 | 欄に意味の無い ID を書いて通す | 検査は存在しか見ない。通ってしまうので、レビューシート (05) の欄の確認で人が本当に上流かを見る。機械では止めない |
| N2 | 本文に「FN-010 参照」と書いて辺にする | 数えない (欄だけを見る)。違反のまま残る |
| N3 | コードの文字列 `"FN-010"` で通す | 数えない (先頭行の `@trace` だけを見る) |
| N4 | 欄に `FN-010 は対象外` と書く | ID として数える (否定は読まない)。欄には ID だけを書く。レビューで止める |
| N5 | 基準ファイルを手で増やす | origin との比較で違反 (§0.3)。origin が無い → `cannot-check` |
| N6 | `@trace` だけ書いて未記入で通す | 警告として件数を末尾に出す。基準の対象にする |
| N7 | 別 branch が同じ ID を振る | T1 で落ちる。`TraceCheck` は他 branch の番号を見ない (番号の補助は ADR-0015 の ID-NEXT の判断待ち) |
| N8 | 空の欄 (`-`) や全角の ID (`ＦＮ-010`) | ID の形ではない。空として扱い、T3〜T6 の欠落で落ちる |
