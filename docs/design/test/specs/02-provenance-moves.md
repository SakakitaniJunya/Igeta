# テスト仕様 — 行の移動・状態の列と、由来・合意の照合

> **TL;DR**: 正本の行を別の文書へ移す・状態の列を足す、という「中身を変えない操作」で顧客への再合意を出さず、
> 逆に「移動を使って再合意を外す」ことも許さない、の両方を決める詳細設計。要点は 3 つ: 1 回の操作の移動は同時に適用する /
> 再合意の規則は「提出したときの文書」と「いまの文書」の厳しいほうで決める / 状態の列の載せ替えは起点の行と機械で比べる

## 0. 規則

用語: **保存値** = 由来のエントリか合意台帳の提出の行に残した指紋。**付け替え** = 由来の `from` を新しい場所へ書き換えること。

| # | 規則 |
|---|---|
| R1 | `moveSourceRows` に渡す 1 回分の移動 (`moves`) は**同時に**適用する。A→B と B→A を同時に渡せば入れ替えになる |
| R2 | 移動 1 件ごとに確かめる: 移した先 (`to`) にいまある行の本文が、元の場所 (`from`) を指す保存値と、その保存値の版で一致すること。一致した移動だけを書く。確かめは、何かを書く前に全部の移動について済ませる |
| R3 | 由来はエントリごと、合意台帳は台帳ごとに確かめる。台帳は、基準の提出以降の全部の提出の保存値が一致したときだけ書く (対応表を通した一致を含む) |
| R4 | 台帳には、1 回の操作につき `source-move` の行を 1 行だけ追記し、確かめられた移動を `moves: [{from, to}, …]` に入れる。過去の行は書き換えない |
| R5 | 台帳を読むとき、`source-move` の行は記録の順に当て、1 行の中の移動は同時に当てる (`場所 = その行の moves のうち from が場所と同じものの to。無ければそのまま`) |
| R6 | 1 回分の移動の中で、同じ `from` が 2 回出る・同じ `to` が 2 回出る・`from` と `to` が同じ、は検査不能にして何も書かない (どの行がどこへ行ったか決まらない) |
| R7 | `agreement-check` が「正本が変わった」と見たとき、再合意の規則 (`reagreementRules`) は、**提出したときの文書** (台帳の提出の行に残る `from` の文書 id を、いまの docs で引いたもの) と**いまの文書** (付け替えを通した先) の両方で判定し、どちらかが当たれば「再合意が要る」。提出したときの文書がもう無いときは、当たるものとして扱う。節の条件は、いまの文書ではいまの見出しで見る。提出したときの文書では節を見ず、kind だけで見る (見出しの記録が無いので、厳しい側に倒す) |
| R8 | 状態の列の載せ替え (`fingerprint-rebase --state-column --base <ref>`): 起点の同じ文書 id・同じ ID の行を元の行とする。(a) いまの表の見出しの最後の列が `状態` (b) いまの行から最後のセルを除いた行が元の行と一致 (c) 元の行の指紋が、保存値の版で保存値と一致、の 3 つを満たすときだけ載せ替える |
| R9 | 保存値の版の実装が無いものは「確かめられない」として、移動も載せ替えも行わない |
| R10 | コマンド `igeta source-move [<dir>] [--dry-run]`: 由来と台帳が指す `from` のうち、いまの場所で保存値と一致しないもの (行・節が無い場合を含む) について、同じ ID (節は同じ見出し) を持つ別の文書の行・節で、保存値とその版で一致するものを探す。ちょうど 1 つなら移動とし、見つけた全部を 1 回分として R1〜R6 で適用する。0 個と 2 個以上は付け替えず、理由を出す。`--dry-run` は何も書かない |

## 1. テストケース一覧

| ID | 層 | 対象 | 前提 (Given) | 操作 (When) | 期待結果 (Then) | 対応 |
|---|---|---|---|---|---|---|
| TST-101 | 結合 | 移動 | 承認済みの提出物と、それが指す要件の行 | 行を、本文を変えずに別の文書へ移し、移動を渡す | 由来の `from` が付け替わり、台帳に 1 行追記、`agreement-check` は適合 | R2・R4 |
| TST-102 | 結合 | 入れ替え | 行 A・B を指す 2 つの由来 | A と B の場所を入れ替え、`[A→B, B→A]` を 1 回で渡す | 両方付け替わり、台帳の 1 行に 2 件、適合 | R1・R5 |
| TST-103 | 結合 | 連鎖 | TST-101 の後 | 同じ行をさらに別の文書へ移す | 台帳は 2 行、行は最後の場所で解決され、適合 | R5 |
| TST-104 | 結合 | 対象外への移動 | 再合意の対象の文書にある行 | 本文を変えずに、対象外の kind の文書へ移す | 適合 (再合意も通知も出ない) | R7 |
| TST-105 | 結合 | 状態の列 | 承認済みの要件の表 | 表に `状態` の列だけを足し、`--state-column --base` で載せ替える | 載せ替わり、承認は保たれ、再合意は出ない | R8 |
| TST-106 | 結合 | 複数の台帳 | 同じ行を指す提出物が 2 つ | 行を移す | 2 つの台帳それぞれに 1 行ずつ追記 | R3 |
| TST-107 | 結合 | 移動を見つける | 行を本文を変えずに別の文書へ移した (移動は渡さない) | `igeta source-move` | 移動を 1 件見つけて適用し、TST-101 と同じ結果になる。`--dry-run` では何も変わらない | R10 |

## 2. 否定テスト (必須)

| ID | 観点 (手口・境界) | ケース | 期待結果 |
|---|---|---|---|
| TST-301 | 書き換えてから移す | 承認の後に対象の行を書き換え、由来を取り直し、対象外の文書へ移す | 台帳に書かない。`agreement-check` は「再合意が要る」のまま |
| TST-302 | 移してから書き換える | 対象の行を、本文を変えずに対象外の文書へ移す (台帳に書かれる)。その後、移した先で書き換える | 「再合意が要る」(提出したときの文書の規則が当たる)。通知だけにならない |
| TST-303 | 元の文書を消す | TST-302 のあと、提出したときの文書を消す | 「再合意が要る」(解決できない = 当たる) |
| TST-304 | 入れ替えで片方だけ変える | A・B を入れ替え、B だった行だけ本文を変える | A の由来は付け替わり適合。B の由来は付け替わらず「再合意が要る」。変えていない行に再合意を出さない |
| TST-305 | 移した先が無い | `to` が解決できない | 付け替えない。台帳に書かない |
| TST-306 | 版の実装が無い | 保存値の版が実装されていない | 付け替えない (確かめられない) |
| TST-307 | 曖昧な移動 | 1 回分に `A→B` と `A→C`、または `A→C` と `B→C` | 検査不能。由来も台帳も 1 バイトも変わらない |
| TST-308 | 状態の列と一緒に書き換える | 状態の列を足し、同じ行の本文も 1 文字変える | 載せ替えない。「再合意が要る」 |
| TST-309 | 別の名前の列 | 最後に足した列の見出しが `状態` でない | 載せ替えない |
| TST-310 | 起点に行が無い | 起点に、その文書 id・その ID の行が無い | 載せ替えない (確かめられない) |
| TST-311 | 追記のみ | どの操作でも | 台帳の既存の行は 1 バイトも変わらない (前の内容が、後の内容の先頭と一致する) |
| TST-312 | 基準より前の提出 | 基準の提出より前の提出だけが一致しない | 書く (照合に使うのは基準以降) |
| TST-313 | 対象の行を消して別の行を同じ ID で置く | 元の場所に同じ ID・違う本文の行を置き、移動は渡さない | 「再合意が要る」(本文が保存値と違う) |
| TST-314 | 候補が割れる | 保存値と一致する同じ ID の行が、別の 2 つの文書にある | `source-move` は付け替えず、理由を出す |
| TST-315 | 書き換えた行を移動と見なす | 行を移し、移した先で 1 文字変えた | `source-move` は移動を見つけない (保存値と一致しない)。「再合意が要る」のまま |

## 3. トレーサビリティ

| 確認 | 結果 |
|---|---|
| テストを持たない ADR-0006 の決定 | 決定 1〜5 (ディレクトリごとの移動、`sourceDoc`・`location` の書き換え、移す段の前後の件数) は [テスト仕様 — 移行コマンド](./07-docs-migrate.md) が持つ |
| いまの実装との差 | (1) `source-move` の行が 1 件ずつ (`from`・`to`) → `moves` の配列に変える (2) 移動を 1 件ずつ順に確かめて書く → 全部を確かめてから同時に書く (3) 規則の判定がいまの文書だけ → 提出したときの文書も見る (4) 状態の列は関数の引数だけ → コマンドの `--state-column --base` から起点の行を読む (5) 移動を渡すコマンドが無い → `igeta source-move` を足す |
| 変えない実装 | 正規化 v3、版に従う照合、`fingerprint-rebase` の対応表、付け替えを記録の順に当てる処理 |
| 機械で確かめられないもの | 台帳のファイルを手で書き換える操作 (版管理の履歴で確かめる。08 の限界と同じ) |
