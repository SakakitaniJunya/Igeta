# テスト仕様 — 人が読む「変わった行」の一覧 (review-sheet --diff)

> **TL;DR**: 人が承認のときに読むのは「変わった行」だけ、を成り立たせる一覧の詳細設計。`review-sheet --diff` が、
> 人の決まりの行の変更・全部読む文書・読む量・追随が要るかもしれない AI の行・AI の側に書かれた人の決めかもしれない行を
> 1 枚に並べる。一覧は読む助けで、合否を決めない (中身は終了コードを変えない)

## 関連

| 区分 | 文書 | 対応 ID |
|---|---|---|
| 上流 (depends_on) | ADR-0002 (条件 4 の却下案の補い・条件 8・条件 11 の限界) / ADR-0008 (決定 7) | — |

## 0. 規則

**決まりの行**の定義は [テスト仕様 — 人の文書の型](./03-person-form.md) の §0 (`core/DecisionRows.ts`)。
読むのは、git の `<起点>` と `<終点>` の commit の内容で、作業ツリーは読まない。文書は frontmatter の id で照らす (移動しても同じ文書)。

| # | 規則 |
|---|---|
| V1 | `review-sheet --diff <起点>..<終点>` は、新しい構成の repo では、V2〜V7 の節をこの順で出し、その後にいままでの出力 (変更ファイル → タスク → 機能 → 要件) を出す。旧い構成では、いままでの出力だけ。新しい構成かどうかは、終点の commit のツリーで見る |
| V2 | **変わった決まり**: `person/` の文書の決まりの行を ID で照らし、足された・消えた・変わった (セルのどれかが違う) 行を、文書ごとに `ID・変更・前・後` の表で並べる。前と後は、ID を除いたセルを ` / ` でつないだもの (状態を含む)。文書の順は終点のパスの文字コード順 (消えた文書は起点のパスで、最後)。行の順は終点の行の順で、消えた行は起点の行の順で後ろに置く。新しい文書は全部の行が「足された」、消えた文書は全部の行が「消えた」 |
| V3 | **表の外の変更**: 決まりの行・frontmatter・生成区間を除いた行 (図のコードフェンスは含む) を、行の文字列の多重集合として比べ、終点にだけある行の数 (足された) と起点にだけある行の数 (消えた) を文書ごとに出す (中身は PR の差分で読む)。どちらも 0 の文書は出さない |
| V4 | **全部読む文書**: 起点と終点の差分で、足された・中身が変わった・移された ADR (`person/decisions/<year>/`)・提出物の章 (`client/delivery/`)・提案書 (`client/proposals/`) の終点のパス |
| V5 | **量**: 全体共通と、V2・V3 に出た文書が属するまとまりの、終点での本文の合計字数と上限 (数え方は 03 の P7) |
| V6 | **追随が要るかもしれない行**: V2 に出た ID ごとに、その修飾 ID を持つ `ai/` の文書の本文の行 (04 §0 の定義。終点のパスと行番号)。無い ID には「なし」と出す |
| V7 | **人の決めかもしれない行**: 終点にだけある `ai/` の文書の本文の行 (04 §0 の定義。V3 と同じ比べ方) のうち、(i) 金額・率・期限の型 (下の表) に当たり、`person/` の文書の修飾 ID を同じ行に持たないもの (ii) 未決の語 (未決・未確定・保留・要確認・宿題・TBD・TODO。英字の語は大文字と小文字を区別せず、前後が英字でないもの) を持つもの |
| V8 | 終了コード: 起点か終点を git から読めなければ検査不能 (2)。V2〜V7 の中身は終了コードを変えない。いままでの出力の「裏取りできない」「申告に無い要件がある」は、`--pr-body` を渡したときだけ、いままでどおり終了コードに出す |

| 型 | 当てる形 (V7。数字は半角と全角) |
|---|---|
| 金額 | `¥`・`￥`・`$` の後に数字 / 数字の後に `円`・`万円`・`億円`・`ドル` |
| 率 | 数字の後に `%`・`％`・`割` |
| 期限 | 数字の後に `分`・`時間`・`日`・`営業日`・`週間`・`か月`・`ヶ月`・`カ月`・`年`、その後に `以内`・`前`・`後`・`まで`・`間` |

## 1. テストケース一覧

| ID | 層 | 対象 | 前提 (Given) | 操作 (When) | 期待結果 (Then) | 対応 |
|---|---|---|---|---|---|---|
| TST-101 | 結合 | 変わった決まり | 起点から、1 本の文書で、行を 1 つ足し、1 つの文を変え、1 つの状態を `仮` から `決定` に変え、1 行を消した (終点では、足した行・文を変えた行・状態を変えた行の順に並ぶ) | `--diff` | 4 行が、終点の行の順 (消えた行は最後) に、「足された」「変わった」「変わった」「消えた」で出る。前と後に状態が見える | V2 |
| TST-102 | 結合 | 表の外 | 結論の 1 行を書き換え、図に 2 行を足した / 別の文書は決まりの行だけを変えた | `--diff` | 前者に「足された 3 行・消えた 1 行」。後者は V3 に出ない | V3 |
| TST-103 | 結合 | 全部読む | ADR を 1 本足し、提出物の章を 1 本変え、提案書を 1 本移した | `--diff` | 3 本の終点のパスが出る | V4 |
| TST-104 | 結合 | 量 | まとまり A の文書を変えた | `--diff` | 全体共通と A の字数と上限が出る (B は出ない) | V5 |

| TST-108 | 結合 | 旧い構成 | 旧い構成の repo | `--diff` | いままでの出力・終了コードと同じ | V1 |

## 2. 否定テスト (必須)

| ID | 観点 (手口・境界) | ケース | 期待結果 |
|---|---|---|---|
| TST-301 | 移動で隠す | 文書を別のフォルダへ移し、同時に 1 行を変える | その行が「変わった」で出る (id で照らす) |
| TST-302 | 消して隠す | 決まりの行を消す / 文書ごと消す | 「消えた」で出る |
| TST-303 | 行を移す | 行を別の文書へ移す | 元の文書で「消えた」、移した先で「足された」 |
| TST-304 | id を変える | 文書の id を変えて中身も変える | 元の id の全部の行が「消えた」、新しい id の全部の行が「足された」 |
| TST-305 | 生成区間 | 決定台帳の生成区間だけが変わった | V2・V3 に出ない |
| TST-306 | 読めない | 無い ref / git の repo でない | 検査不能 (2) |
| TST-307 | 型の境界 | `ai/` の足した行の「3 日」(後ろの語なし)・「v2.0」・コードフェンスの中の「30%」・`Mastodon` (TODO を含む語) | 出ない |
| TST-308 | 変わっていない行 | `ai/` の文書の、この差分で変わっていない行に「30%」 | 出ない |
| TST-309 | 作業ツリー | 終点の commit の後に、作業ツリーで人の文書を書き換えた | 一覧は変わらない (commit の内容だけを読む) |

## 3. トレーサビリティ

| 確認 | 結果 |
|---|---|
| ADR との対応 | ADR-0008 決定 7 (人が読むのは変わった行) = V2〜V4 / ADR-0002 条件 8 (量を一覧に出す) = V5 / 条件 4 の却下案の補い (行の追随) = V6 / 条件 11 の限界と ADR-0005 の「詳細設計で決めた論点」(型の一覧) = V7 |
| いまの実装との差 | `--diff` は変更ファイルから要件を辿る出力だけを持ち、タスクの文書が無いと終了コード 2 を返す。V2〜V7 は未実装。V8 は、`--pr-body` が無いときの終了コードを変える (新しい構成だけ) |
| 機械で確かめないもの | V7 の型に当たらない書き方 (「三割」「半額」) / V7 の行に、関係のない `person/` の修飾 ID を添えて一覧から消す書き方 / 決まりの表の外に書いた決まり (V3 の行数にしか出ない。決まりの表に書くことは 03 の P4 が ○ の kind に求める) |

## 4. テストデータ (任意)

一時フォルダの git repo に、起点と終点の 2 つの commit を作る。題材は架空の予約業務。個人情報は無い。
