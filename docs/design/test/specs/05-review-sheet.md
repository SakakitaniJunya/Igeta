# テスト仕様 — 人が読む「変わった行」の一覧 (review-sheet --diff)

> **TL;DR**: 人が承認のときに読むのは「変わった行」だけ、を成り立たせる一覧の詳細設計。`review-sheet --diff` が、
> 人の決まりの行の変更・全部読む文書・読む量・追随が要るかもしれない AI の行・AI の側に書かれた人の決めかもしれない行を
> 1 枚に並べる。一覧は読む助けで、門ではない (終了コードを変えない)。門の workflow が job の要約に出す

|---|---|---|

## 0. 規則

**決まりの行**の定義は [テスト仕様 — 人の文書の型](./03-person-form.md) の P3 と同じ読み方 (`core/DecisionRows.ts`) を使う。

| # | 規則 |
|---|---|
| V1 | `review-sheet --diff <起点>..<終点>` は、新しい構成の repo では、いままでの出力 (変更ファイル → タスク → 機能 → 要件) の前に V2〜V7 の節をこの順で出す。旧い構成では、いままでの出力だけ |
| V2 | **変わった決まり**: `person/` の文書を frontmatter の id で照らし (移動しても同じ文書)、決まりの行を ID で照らす。足された・消えた・変わった (セルのどれかが違う) 行を、文書ごとに `ID・変更・前・後` の表で並べる。前と後は、ID を除いたセルを ` / ` でつないだもの (状態を含む)。新しい文書は全部の行が「足された」、消えた文書は全部の行が「消えた」 |
| V3 | **表の外の変更**: 決まりの行と frontmatter を除いた行のうち、足された行の数と消えた行の数を文書ごとに出す (中身は PR の差分で読む) |
| V4 | **全部読む文書**: 足された・変わった ADR (`person/decisions/<year>/`)・提出物の章 (`client/delivery/`)・提案書 (`client/proposals/`) のパス |
| V5 | **量**: 全体共通と、変わった文書が属するまとまりの、本文の合計字数と上限 (数え方は 03 の P7 と同じ) |
| V6 | **追随が要るかもしれない行**: V2 に出た ID ごとに、その修飾 ID を持つ `ai/` の文書の行 (パスと行番号)。無ければ「なし」 |
| V7 | **人の決めかもしれない行**: この差分で足された・変わった `ai/` の文書の本文の行のうち、(i) 金額・率・期限の型 (下の表) に当たり、`person/` の文書の修飾 ID を同じ行に持たないもの (ii) 未決の語 (未決・未確定・保留・要確認・宿題・TBD・TODO) を持つもの |
| V8 | 起点か終点を git から読めなければ検査不能 (2)。V2〜V7 の中身は終了コードを変えない |

| 型 | 当てる形 (V7) |
|---|---|
| 金額 | `¥`・`￥`・`$` の後に数字 / 数字の後に `円`・`万円`・`億円`・`ドル` |
| 率 | 数字の後に `%`・`％`・`割` |
| 期限 | 数字の後に `分`・`時間`・`日`・`営業日`・`週間`・`か月`・`ヶ月`・`カ月`・`年`、その後に `以内`・`前`・`後`・`まで`・`間` |

| TST-102 | 結合 | 表の外 | 結論の 1 行と図を変えた | `--diff` | その文書に「足された n 行・消えた m 行」 | V3 |

## 2. 否定テスト (必須)

| ID | 観点 (手口・境界) | ケース | 期待結果 |
|---|---|---|---|
| TST-301 | 移動で隠す | 文書を別のフォルダへ移し、同時に 1 行を変える | その行が「変わった」で出る (id で照らす) |
| TST-302 | 消して隠す | 決まりの行を消す / 文書ごと消す | 「消えた」で出る |
| TST-303 | 行を移す | 行を別の文書へ移す | 元の文書で「消えた」、移した先で「足された」 |
| TST-304 | id を変える | 文書の id を変えて中身も変える | 元の id の全部の行が「消えた」、新しい id の全部の行が「足された」 |
| TST-305 | 状態だけ変える | 文は同じで状態だけ `未決` から `決定` | 「変わった」で出る |
| TST-306 | 生成区間 | 決定台帳の生成区間だけが変わった | V2 に出ない (生成物は元の行の変更として出ている) |
| TST-307 | 読めない | 無い ref / git の repo でない | 検査不能 (2) |
| TST-308 | 型の境界 | `ai/` の行の「3 日」(後ろの語なし)・「v2.0」・コードフェンスの中の「30%」 | 出ない |
| TST-309 | 変わっていない行 | `ai/` の文書の、この差分で変わっていない行に「30%」 | 出ない (差分の行だけを見る) |

## 3. トレーサビリティ

| 確認 | 結果 |
|---|---|
| ADR との対応 | ADR-0008 決定 7 (人が読むのは変わった行) = V2〜V4 / ADR-0002 条件 8 (量を一覧に出す) = V5 / 条件 4 の却下案の補い (行の追随) = V6 / 条件 11 の限界と ADR-0005 の「実装で決める論点」(語の一覧) = V7 |
| いまの実装との差 | `--diff` は変更ファイルから要件を辿る出力だけを持つ。V2〜V7 は未実装 |
| 機械で確かめられないもの | V7 の型に当たらない書き方 (「三割」「半額」) は出ない。V7 は気づくための一覧で、人の決めが `ai/` に無いことの証明ではない |

## 4. テストデータ (任意)

一時フォルダの git repo に、起点と終点の 2 つの commit を作る。題材は架空の予約業務。個人情報は無い。
