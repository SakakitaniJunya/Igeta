# テスト仕様 — 移行コマンド (docs-migrate)

> **TL;DR**: 既存の repo を 3 フォルダの構成へ「移す段」を、機械が適用まで行うための詳細設計。止める条件は書く前に全部
> 確かめ、書いた後は完了条件 (リンク・置き場所・索引・由来と合意の状態・文書の集合と本文) を確かめる。推定で置かず、
> 捨てたものを黙らず、commit はしない。「書き直す段」は人と AI の作業で、コマンドは作業の列と報告を出す

| M2 | 対象は docs/ の下の全部のファイル。除くのは `nonDocPaths`・docs/ 直下の `dependencies.md`・README.md (どの階層でも。索引は作り直す)。移行元の構成を問わず、文書ごとに「いまの場所」と「置き場所の表から決まる場所」を比べ、違うものを移す。2 回目の実行は何も変えない |

| M4 | 行き先は `Role.ts` の置き場所の型から決める。型が名前を固定する文書 (地図・決定台帳・約束・実装順序・全体共通の固定の文書・用語集) は決まった名前、ほかはいまのファイル名のまま。全体共通の固定の文書の名前は 1 つの表に持ち、雛形のファイル名と突き合わせる |
| M5 | まとまりは frontmatter の `context`。無い文書は `shared` に置き、一覧で知らせる。約束 (context-contract) とまとまりの地図は、`context` が無いか `shared` なら S5 |
| M6 | ADR は `person/decisions/<年>/`、提案書は `client/proposals/<年>/`。年は `created` (無ければ `proposed`・`adopted`・`accepted` の順) の年。どれも無ければ S5 |
| M7 | 提出物は、章のあるフォルダを丸ごと `client/delivery/<提出物名>/` へ移す (章・由来・台帳・ログ・manifest・その下の全部のファイル)。提出物名はフォルダ名。フォルダ名が `delivery` のときは manifest の `output` から拡張子を除いた名前で、manifest も無ければ S5。章が下位のフォルダにある・manifest がフォルダの外を指すなら S5 |
| M8 | 文書でないファイル (画像など) は、それをリンクか画像で使う文書が全部同じフォルダにあり、同じフォルダへ移り、ファイルがそのフォルダかその下にあるときだけ、文書からの相対位置を保って一緒に移す。当てはまらなければ S6 (人が移すか `nonDocPaths` に足す) |
| M9 | 移した後に 15 本を超える `ai/specs/tasks/`・`ai/handbook/{how-to,explanation,runbooks}/` は、全部をまとまりの下位フォルダへ置く。ほかのフォルダの超過は、書き直す段の作業の列に出す |
| M10 | **順序**: ① 前の状態を測る (由来と合意の 1 件ずつの状態・壊れているリンク・文書の id と本文) ② 指紋を載せ替える (`fingerprint-rebase`) ③ 手引きの写しを消す (M11) ④ ファイルを移し、空になったフォルダを消す ⑤ リンクを書き換える (M12) ⑥ 由来の `sourceDoc` と食い違いログの `location` を書き換える ⑦ 古い索引を消し、入口を替える (M14) ⑧ 承認の割り当てのファイルを置く (M15)。ADR が 1 本でもあり `person/decisions/README.md` が無ければ雛形から置く ⑨ 索引を再生成する ⑩ 完了条件を確かめる |
| M11 | 手引きの写し (kind が document-taxonomy・human-review・provenance-workflow) は、本文 (frontmatter を除き、リンクの行き先・行末の空白・改行の種類を無視) の SHA256 が、Igeta の過去の版の手引きの値の表にあれば消す。その id を指す `depends_on`・`relates_to` を外し、写しへの本文のリンクは、リンクを外して文字を残し、後ろに版の手引きのパスをコードスパンで足す (一覧で知らせる)。表に無ければ S3。値の表はコードに固定する |
| M12 | リンク: 書き換えるのは、指紋の正規化 v3 が id に置き換えるのと同じ形 (`[…](…)`・`![…](…)`) の相対パス。対象は、repo の中の追跡されている全部の `.md` (docs/ の外を含む)。`#` より後ろは保つ。コードフェンス・コードスパン・生成区間の中は書き換えない |
| M13 | リンクでない旧いパス (参照の形の定義・HTML・コードスパン・コードのコメント・設定・CI の定義・`package.json`) は書き換えず、追跡されている全部のテキストから、移した文書の旧い repo 相対パスの文字列を探して一覧で知らせる |
| M14 | README.md: 新しい置き場所に対応しないフォルダの README.md を消す (3 フォルダの中に残る古いフォルダの分を含む)。区間の外に、見出しと目的の 1 行のほかの文章を持つものは、その行を一覧で知らせる。docs/README.md の入口は、いままでの 3 行と 1 字も違わないときだけ新しい 3 行に替え、違えば知らせる |
| M15 | 承認の割り当てのファイル (`AGENTS.md`・`.github/CODEOWNERS`) は、`init` と同じ作り手で置く (06 の I8)。`.igeta.json` に `sharedKinds` があれば、新しい構成では読まないことを知らせる |
| M16 | **完了条件**: 1 つでも欠ければ終了コード 1 で、作業ツリーを戻す手順を出す。(C1) 追跡している全部の `.md` の本文リンクのうち、①で壊れていなかったものが壊れていない (前から壊れていたものは一覧で知らせる) (C2) 置き場所の違反 (ADR-0002 条件 2・15) が 0 件で、`docs/common/` が無い (C3) 索引のずれ 0 件 (C4) 由来のエントリと合意の照合の 1 件ずつの状態が①と同じ (C5) 文書の id の集合が、消した手引きの写しを除いて①と同じ (README.md は数えない)。移した文書の本文は、リンクの行き先を除いて①と同じ (M11 でリンクを外した行を除く)。文書でないファイルは 1 つも失われていない |
| M17 | 完了条件を満たした後に残る違反 (人の文書の型と量・依存の向き・届かない AI の文書・引かれていない ADR・15 本の超過・AI の文書の未決の節) は、書き直す段の作業の列として、種類ごとの件数と一覧を出す (終了コード 0) |
| M18 | `--dry-run` は、止める条件と計画を出し、何も書かない (止める条件が無ければ終了コード 0)。計画の行は `MOVE <旧> -> <新>`・`DELETE <パス> (<理由>)`・`CREATE <パス>`・`APPEND <パス>`・`REWRITE <パス> (<件数> 件)`・`NOTICE <種類>: <内容>` で、種類ごとにパスの文字コード順 |
| M19 | `--split-report` は、由来と台帳が指す正本のうち保存値と一致しないものを、章・`from`・いまの場所・再合意の規則に当たるか・取れる操作 (取り直して承認し直す / 顧客へ新しい版を出す) で並べる。承認済みの版を持つ台帳がある repo では、移す段の計画に「書き直す段で要件の行を変えると再合意が出る」と知らせる |

## 4. テストデータ (任意)

一時フォルダの git repo に fixture を作る。題材は架空の予約業務で、個人情報は無い。
v3 の構成の fixture: 旧い種類別のフォルダ (`design/basic/` など) を `docs/common/`・`docs/ai/specs/`・`docs/person/`・`docs/client/delivery/<名前>/` の下へ
そのまま移し、ADR は `docs/adr/` に残した形 (3 フォルダはあるが、置き場所の表のパスになっていない)。
