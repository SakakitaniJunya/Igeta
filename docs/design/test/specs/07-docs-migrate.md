# テスト仕様 — 移行コマンド (docs-migrate)

> **TL;DR**: 既存の repo を 3 フォルダの構成へ「移す段」を、機械が適用まで行うための詳細設計。止める条件は書く前に全部
> 確かめ、書いた後は完了条件 (リンク・置き場所・索引・由来と合意の件数・文書の集合) を確かめる。推定で置かず、
> 捨てたものを黙らず、commit はしない。「書き直す段」は人と AI の作業で、コマンドは作業の列と報告を出す

## 0. 規則

| # | 規則 |
|---|---|
| M1 | `igeta docs-migrate --owner <持ち主> [--dry-run]` は移す段を適用まで行い、commit しない。`--split-report` は書き直す段のための報告だけを出す (何も書かない) |
| M2 | 対象は docs/ の下の全部のファイル (`nonDocPaths` と docs/ 直下の生成索引 2 本を除く)。移行元の構成 (旧い構成・v3) を問わず、文書ごとに「いまの場所」と「置き場所の表から決まる場所」を比べ、違うものを移す。2 回目の実行は何も変えない |
| M3 | **止める条件** (1 つでもあれば、全部を一覧で出し、何も書かずに終わる): (S1) 作業ツリーが clean でない・git の repo でない (S2) kind の無い文書・表に無い kind (S3) Igeta の手引きの写しで、どの版の手引きとも一致しないもの (M11) (S4) 行き先が重なる。全体共通の固定の文書が同じ kind で 2 本ある場合と、直下か `docs/` に CODEOWNERS がある場合を含む (S5) 行き先を決められない文書 (M5〜M7) (S6) 行き先を決められない、文書でないファイル (M8) (S7) 由来・台帳・食い違いログ・`.igeta.json` が読めない (S8) `--owner` が無い・形が違う |
| M4 | 行き先は `Role.ts` の置き場所の型から決める。型が名前を固定する文書 (地図・決定台帳・約束・実装順序・全体共通の固定の文書・用語集) は決まった名前、ほかはいまのファイル名のまま。全体共通の固定の文書の名前は 1 つの表に持ち、雛形のファイル名と突き合わせる |
| M5 | まとまりは frontmatter の `context`。無い文書は `shared` に置き、一覧で知らせる。約束 (context-contract) とまとまりの地図に `context` が無ければ S5 |
| M6 | ADR は `person/decisions/<年>/`、提案書は `client/proposals/<年>/`。年は `created` (無ければ `proposed`・`adopted`・`accepted` の順) の年。どれも無ければ S5 |
| M7 | 提出物は、manifest (`deliverable.json`) のあるフォルダを丸ごと `client/delivery/<提出物名>/` へ移す (章・由来・台帳・ログ・その下の全部のファイル)。提出物名はフォルダ名。フォルダ名が `delivery` のときは manifest の `output` から拡張子を除いた名前。章がフォルダの外にある・manifest がフォルダの外を指すなら S5 |
| M8 | 文書でないファイル (画像など) は、それをリンクか画像で使う文書が全部同じフォルダにあり、同じフォルダへ移り、ファイルがそのフォルダかその下にあるときだけ、文書からの相対位置を保って一緒に移す。当てはまらなければ S6 (人が移すか `nonDocPaths` に足す) |
| M9 | 移した後に 15 本を超える `ai/specs/tasks/`・`ai/handbook/{how-to,explanation,runbooks}/` は、全部をまとまりの下位フォルダへ置く。ほかのフォルダの超過は、書き直す段の作業の列に出す |
| M10 | **順序**: ① 由来と合意の件数を測る ② 指紋を載せ替える (`fingerprint-rebase`。リンクを書き換える前) ③ ファイルを移す ④ リンクを書き換える ⑤ 由来の `sourceDoc` と食い違いログの `location` を書き換える ⑥ 手引きの写しを消す ⑦ 古い索引を消し、入口を替える ⑧ 門のファイルを置く ⑨ 索引を再生成する ⑩ 完了条件を確かめる |
| M11 | 手引きの写し (kind が document-taxonomy・human-review・provenance-workflow) は、本文 (frontmatter を除き、リンクの行き先・行末の空白・改行の種類を無視) の SHA256 が、Igeta の過去の版の手引きの値の表にあれば消し、その id を指す `depends_on`・`relates_to` を外す。無ければ S3。値の表はコードに固定し、テストが git のタグから計算して突き合わせる |
| M12 | リンク: 書き換えるのは、指紋の正規化 v3 が id に置き換えるのと同じ形 (`[…](…)`・`![…](…)`) の相対パス。対象は、repo の中の追跡されている全部の `.md` (docs/ の外を含む)。`#` より後ろは保つ。コードフェンス・コードスパン・生成区間の中は書き換えない |
| M13 | リンクでない旧いパスの文字列 (コードスパン・コードのコメント・設定・CI の定義・`package.json`) は書き換えず、追跡されている全部のテキストから探して一覧で知らせる |
| M14 | README.md: 3 フォルダの外に残る古い索引は消す。区間の外に、見出しと目的の 1 行のほかの文章を持つものは、その行を一覧で知らせる。docs/README.md の入口は、いままでの 3 行と 1 字も違わないときだけ新しい 3 行に替え、違えば知らせる |
| M15 | 門のファイル: `AGENTS.md` が無ければ雛形から作り、あって `docs/person`・`docs/ai` に触れていなければ入口の節を末尾に足す。`.github/CODEOWNERS` が無ければ作り、あれば足りない行を末尾に足す。門の workflow が無ければ作り、あれば触らずに知らせる。内容は `init` と同じ作り手 (1 つの実装) |
| M16 | **完了条件** (1 つでも欠ければ終了コード 1 で、作業ツリーを戻す手順を出す): (C1) 壊れた本文リンク 0 件 (C2) 置き場所の違反 0 件で、`docs/common/` が無い (C3) 索引のずれ 0 件 (C4) 由来と合意の結果の件数 (適合・要確認・再合意が要る・通知) が①と同じ (C5) 文書の id の集合が、消した手引きの写しを除いて前と同じ |
| M17 | 完了条件を満たした後に残る違反 (人の文書の型と量・依存の向き・届かない AI の文書・引かれていない ADR・15 本の超過・AI の文書の未決の節) は、書き直す段の作業の列として、種類ごとの件数と一覧を出す (終了コード 0) |
| M18 | `--dry-run` は、止める条件と計画 (`MOVE`・`DELETE`・`CREATE`・`REWRITE`・`NOTICE` の行。パスの順) を出し、何も書かない |
| M19 | `--split-report` は、由来と台帳が指す正本のうち保存値と一致しないものを、章・`from`・いまの場所・再合意の規則に当たるか・取れる操作 (状態の列の載せ替え / 行の移動の付け替え / 取り直して承認し直す / 顧客へ新しい版を出す) で並べる |
