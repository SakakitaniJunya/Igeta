# テスト仕様 — 人の文書の型・量・書き込み口 (PersonFormCheck)

> **TL;DR**: `docs/person/`・`docs/client/` の文書が、人が全部読んで決められる型と量を保つための検査の詳細設計
> (ADR-0002 の条件 5〜10)。`template-check` の中で動き、門の workflow が起点を渡して実行する。
> 決まりの行の見分け方・数え方・`廃` の行の比べ方を §0 に固定し、§2 に検査を抜けようとする書き方を並べる

## 0. 規則

| # | 規則 |
|---|---|
| P1 | 対象は、新しい構成の repo の `docs/person/**`・`docs/client/**`。旧い構成の repo では何も出さない |
| P2 | 文書の kind は、frontmatter の `kind` と置き場所の型の両方から決める。食い違う・決まらない文書は、型の検査をしない (置き場所の検査が違反にする) |
| P3 | **決まりの行** = 表 (見出しの行と区切りの行を持つ。コードフェンス・生成区間の外) の行で、最初のセルが「その kind の雛形の ID の接頭辞 + `-` + 3 桁」で始まるもの。飾り (`**BF-113**`) を付けた行は ID の行ではない |
| P4 | 型の検査が ○ の kind: 決まりの行を持つ表が 1 つ以上ある。その表の見出しの最後の列は `状態`。決まりの行は、列の数が見出しと同じで、最後のセルが `決定`・`仮`・`未決`・`廃` のどれか |
| P5 | 図が要る kind: ` ```mermaid ` のコードフェンスが 1 つ以上ある。他のコードフェンスの中の例と、画像のリンクは数えない |
| P6 | 行数: ○ の kind は 100 行、requirements は 150 行まで。frontmatter を含めて数え、末尾の改行 1 つと生成区間の行は数えない |
| P7 | 合計字数: 全体共通 (`person/requirements/**` + `person/design/shared/**`) は 30,000 字、まとまり (`person/design/<c>/**`) は 15,000 字まで。1 字 = Unicode の 1 文字 (全角も半角も 1)。frontmatter・コードフェンス・改行・各フォルダの README.md は数えない。超えたら警告で、Igeta のメジャー版が 1 以上なら違反。版を読めなければ検査不能 |
| P8 | `廃` の行: (a) 同じ文書の中で、`廃` の ID を別の行に使ったら違反。(b) 起点 (`--base <ref>`) があれば、起点の `person/` の文書で `廃` だった行が、いまも同じ文書 (frontmatter の id で照らす) に `廃` のまま無ければ違反。文書を消す・id を変える・行を別の文書へ移す、はどれも「消した」に当たる。起点を読めなければ検査不能 |
| P9 | 書き込み口 (README.md を含む全部の文書): HTML コメントは違反 (コードフェンスの中の例は除く)。生成区間は `dir-index` (各フォルダの README.md)・`adr-index` (`person/decisions/README.md`)・`tentative-index` (決定台帳) の 3 種だけで、決まった文書に 1 つずつ、閉じていて、入れ子にしない。README.md は、区間の外に frontmatter・見出し・目的の 1 行だけ |
| P10 | 行が増えて上限を超えたときに別の文書へ移すのは、`廃` でない行だけ (`廃` の行は元の文書に残す) |

## 2. 否定テスト (必須)

| ID | 観点 (手口・境界) | ケース | 期待結果 |
|---|---|---|---|
| TST-301 | 表が無い | ○ の kind に決まりの表が 1 つも無い (ID に飾りを付けて行を隠した場合を含む) | 違反 |
| TST-302 | 状態の列が無い | 決まりの行を持つ表の最後の列が `状態` でない | 違反 (見出しの行) |
| TST-303 | 状態の値 | 最後のセルが `確定`・空・`決定 (仮)` | 違反 (その行) |
| TST-304 | 列の数 | 決まりの行の列の数が見出しと違う | 違反 (その行) |
| TST-305 | 図が無い | 図が要る kind に、画像のリンクだけ / 別のコードフェンスの中の mermaid だけ | 違反 |
| TST-306 | 行数 | ○ の kind が 101 行 / requirements が 151 行 | 違反 |
| TST-307 | コメント | 1 行のコメント / 複数行のコメント / 生成区間の中のコメント | どれも違反。コードフェンスの中の例は通す |
| TST-308 | 生成区間 | 管理外の名前 / 決まった文書以外に置く / 同じ区間が 2 つ / 閉じていない / 入れ子 / 終わりだけ | どれも違反 |
| TST-309 | README.md | 区間の外に文章が 2 行以上 | 違反 |
| TST-310 | 廃を消す | 起点で `廃` の行を消す / 状態を `決定` に戻す / 同じ ID を別の行に使う / 文書ごと消す / 文書の id を変える / 行を別の文書へ移す | どれも違反 |
| TST-311 | 起点が読めない | 無い ref / git の repo でない / docs が repo の外 | 検査不能 |
| TST-312 | 雛形の不備 | ○ の kind の雛形に ID の接頭辞が無い | 検査不能 (kind ごとに 1 件) |
| TST-313 | 版が読めない | 合計が上限を超えていて、Igeta の版を読めない | 検査不能 (警告にも違反にも倒さない) |
| TST-314 | client の文書 | 提出物の章に HTML コメント | 違反 |
