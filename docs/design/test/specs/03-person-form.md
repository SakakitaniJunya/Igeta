# テスト仕様 — 人の文書の型・量・書き込み口 (PersonFormCheck)

> **TL;DR**: `docs/person/`・`docs/client/` の文書が、人が全部読んで決められる型と量を保つための検査の詳細設計
> (ADR-0002 の条件 5〜10)。`template-check` の中で動く。「決まりの行」の定義をここに 1 つだけ置き、
> 文書のつながり (04) とレビューシート (05) はこの定義を使う。§2 に検査を抜けようとする書き方を並べる

## 0. 規則

**定義** (04・05 も使う。実装は `core/DecisionRows.ts` の 1 か所)

| 語 | 定義 |
|---|---|
| ID の形 | 英大文字で始まる英大文字と数字の接頭辞 + `-` + 数字 3 桁 (例: `BF-113`)。4 桁以上・小文字・全角・飾り (`**BF-113**`) は ID の形ではない |
| 決まりの表 | 表 (見出しの行と区切りの行を持つ。コードフェンス・生成区間・HTML コメントの外) のうち、見出しの最後の列が `状態` のもの |
| 決まりの行 | 決まりの表のデータの行で、最初のセルが ID の形だけのもの |

| # | 規則 |
|---|---|
| P1 | 対象は、新しい構成の repo の `docs/person/**`・`docs/client/**`。旧い構成の repo では何も出さない |
| P2 | 文書の kind は frontmatter の `kind`。無ければ置き場所の型から決める。frontmatter の `kind` と置き場所の型が別の kind を指すときは、型の検査をしない (置き場所の検査が違反にする) |
| P3 | 決まりの表のデータの行は、全部が決まりの行でなければならない (最初のセルが ID の形だけ)。列の数は見出しと同じで、最後のセルは `決定`・`仮`・`未決`・`廃` のどれか。`person/` のどの kind の文書にも当てる |
| P4 | 型の検査が ○ の kind: その kind の接頭辞 (雛形の `id_prefix`・`id_prefixes`) の決まりの行が 1 つ以上ある。その接頭辞の ID を最初のセルに持つ行が、決まりの表でない表にあれば違反 |
| P5 | 図が要る kind: ` ```mermaid ` のコードフェンスが 1 つ以上ある。他のコードフェンスの中の例と、画像のリンクは数えない |
| P6 | 行数: ○ の kind は 100 行、requirements は 150 行まで。frontmatter を含めて数え、末尾の改行 1 つと生成区間の行は数えない |
| P7 | 合計字数: 全体共通 (`person/requirements/**` + `person/design/shared/**`) は 30,000 字、まとまり (`person/design/<c>/**`) は 15,000 字まで。1 字 = Unicode の 1 文字 (全角も半角も 1)。frontmatter・コードフェンス・改行・各フォルダの README.md は数えない。超えたら警告で、Igeta のメジャー版が 1 以上なら違反。版を読めなければ検査不能 |
| P8 | `廃` の行: (a) 同じ文書の中で、`廃` の ID を別の行に使ったら違反。(b) 起点 (`--base <ref>`) があれば、起点の `person/` の文書で `廃` だった行が、いまも同じ文書 (frontmatter の id で照らす) に `廃` のまま無ければ違反。文書を消す・id を変える・行を別の文書へ移す、はどれも「消した」に当たる。起点を読めなければ検査不能 |
| P9 | 書き込み口 (README.md を含む全部の文書): HTML コメントは違反 (コードフェンスの中の例は除く)。生成区間は `dir-index` (各フォルダの README.md)・`adr-index` (`person/decisions/README.md`)・`tentative-index` (決定台帳) の 3 種だけで、決まった文書に 1 つずつ、閉じていて、入れ子にしない。README.md は、区間の外に frontmatter・見出し・目的の 1 行だけ |
| P10 | 行が増えて上限を超えたときに別の文書へ移すのは、`廃` でない行だけ (`廃` の行は元の文書に残す) |

## 3. トレーサビリティ

| 確認 | 結果 |
|---|---|
| ADR-0002 の条件との対応 | 条件 5 = P3・P4 / 条件 6 = P5 / 条件 7 = P6 / 条件 8 = P7 / 条件 9 = P8・P10 / 条件 10 = P9 |
| いまの実装との差 | `PersonFormCheck` は branch `feat/v4-person` にあり、統合していない。差は 2 つ: (1) 状態の検査が自分の接頭辞の行だけ → 決まりの表の全部の行に当てる (P3) (2) 最初のセルが ID の形だけであることの検査が無い → 足す (P3)。P2・P5〜P9 は規則のとおり |
| 起点の渡し方 | CI は PR の merge-base を `--base` に渡す。手元では省略でき、そのときは P8 (a) だけを見る |
| 機械で確かめないもの | 結論が 3 行までか・節の順序・「決めてほしいこと」の有無 (雛形が示し、人が承認のときに見る) / frontmatter の中のコメントと自由記述 / HTML コメント以外の見えない書き方 (`[//]: #` の形・`hidden` の要素・ゼロ幅の文字) / コードフェンスの中に文章を書いて字数を逃がす書き方 / `.md` 以外のファイル / kind の付け方が内容に合っているか / `廃` の行に移動先を書いていないか / `決定`・`仮`・`未決` の行を消すこと (05 の一覧が「消えた」として並べる) |

## 4. テストデータ (任意)

一時フォルダに新しい構成の docs と git repo を作る。雛形の ID の接頭辞は、テスト用の対応表で渡す。個人情報は無い。
